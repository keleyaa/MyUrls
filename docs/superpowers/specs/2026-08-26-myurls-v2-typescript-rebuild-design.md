# MyURL v2 全栈重构产品需求与技术设计规格

**日期：** 2026-08-26

**状态：** 交互式设计已批准，等待书面规格审查

**目标技术栈：** TypeScript、Fastify、Redis、Svelte、Vite

**目标部署：** 单 VPS，Docker Compose 交付 `app + redis`

**版本定位：** 全新 v2，不兼容旧 Go 版本的数据、接口或部署方式

## 1. 文档目的

本文档是 MyURL v2 的产品需求文档（PRD）与技术设计基线，用于约束后续实现计划、开发、测试、验收和发布。所有实现任务必须能追溯到本文档中的需求、接口或质量门禁；未在本文档中定义的产品能力默认不属于 v2 首版范围。

本文档不承诺通过一次编码消除所有交付风险。项目通过阶段门禁、真实依赖测试、可回滚发布和验收证据降低风险；任一门禁失败时停止推进，不以跳过验证换取进度。

## 2. 背景与产品定位

现有 MyUrls 是 Go、Gin、Redis 和原生前端实现。v2 不以兼容旧实现为目标，而是围绕一个更现代、更小、更明确的公开短链工具重新设计：用户无需注册，粘贴目标 URL 后执行一次主操作，即可获得并复制一个固定有效 90 天的短链接。

产品面向两类用户：

1. 需要快速缩短链接的普通用户，希望页面无需学习、无需注册、步骤尽可能少。
2. 自行部署服务的技术用户，希望镜像小、依赖少、配置明确，并能接入自己已有的反向代理或隧道方案。

## 3. 目标与成功标准

### 3.1 产品目标

1. 将主流程压缩为「粘贴 URL → 生成并复制」。
2. 默认不显示验证码，仅在风险触发后渐进式启用 Cloudflare Turnstile。
3. 提供可选自定义别名，但不让低频能力干扰默认路径。
4. 以暗色开发者工具台风格建立稳定、现代且长期耐看的视觉识别。
5. 使用 Redis 原子写入和固定 TTL 提供可预测的短链生命周期。
6. 以单应用容器和单 Redis 容器完成可独立部署的最小运行栈。

### 3.2 可验证成功标准

1. 用户粘贴有效 URL 后，只需触发一次主操作即可完成短链创建；浏览器允许剪贴板访问时同时完成复制。
2. 浏览器阻止自动复制时，短链结果仍完整可见，整条结果可作为一个大点击目标再次复制。
3. 自动短码、自定义别名、过期、冲突、限流、挑战和依赖故障均有确定的 HTTP 语义和前端反馈。
4. 桌面与移动端均无横向溢出、不可读文本、控件重叠或被遮挡的核心操作。
5. Compose 重启后未过期短链仍可跳转；备份能够在干净环境中恢复。
6. 全新克隆按文档可完成构建、启动、验证和回滚，无需读取旧 Go 运行时代码。
7. 所有第 19 节定义的质量门禁通过后，候选版本才具备合并资格。

### 3.3 运行时不采集的产品指标

v2 首版不引入分析或遥测，因此不以线上转化率、活跃用户数或点击量作为验收依据。主流程步数、响应时间、错误语义、可访问性、视觉回归和恢复能力通过自动化及人工验收验证。

## 6. 用户体验与交互规格

### 6.1 信息架构

产品只有一个公开工具页，不设置营销落地页或多级导航。页面从上到下由以下区域组成：

1. 顶部品牌栏：左侧 `myurl`，右侧低强调服务状态。
2. 中央品牌区：`myurl` 主标题和一句简短中文说明。
3. 链接编辑器：URL 输入、唯一主操作和折叠的自定义别名。
4. 结果区：成功后原位出现，可整条点击再次复制。
5. 页脚：左侧 GitHub 项目，中间订阅转换入口，右侧 `Open source · MIT`。

顶部服务状态在页面加载后请求 `/health/ready` 得出：成功显示 `service online`，失败显示 `service degraded`。该检查不阻塞页面渲染，也不能替代创建请求自身的错误处理。

### 6.2 默认创建流程

1. 页面加载后焦点可直接进入 URL 输入框。
2. 用户粘贴绝对 HTTP(S) URL。
3. 用户点击「生成并复制」或按 Enter；两者走同一提交路径。
4. 前端立即进入提交状态，禁用重复提交并保留原输入。
5. 服务端返回成功后，前端展示短链并尝试写入剪贴板。
6. 自动复制成功时显示「已生成并复制 · 90 天后自动失效」。
7. 自动复制失败时显示「短链已生成 · 点击结果即可复制」，结果整体保持可聚焦、可点击。

浏览器可能因权限、非安全上下文或用户激活时效阻止异步请求完成后的剪贴板写入。因此「一步生成并复制」是优先路径，但不是所有浏览器中的绝对保证；产品必须保留不丢失结果的单次降级操作。

### 6.3 自定义别名

- 默认隐藏，仅显示「自定义别名」低强调入口。
- 展开后在同一编辑器内部显示，不打开弹窗或新页面。
- 前端输入即时转为小写，并展示允许字符及长度反馈。
- 收起别名区域不得清除已输入内容，除非用户开始一次全新的成功创建流程。
- 别名冲突时保留 URL 与别名，允许用户原位修改后重试。

### 6.4 渐进式挑战

1. 普通低风险请求不加载 Turnstile 脚本。
2. API 返回 `challenge_required` 后，页面在编辑器内展开验证区域。
3. 验证成功后，页面携带 token 自动重提原创建请求，不要求用户再次点击主按钮。
4. 验证失败或过期时保留输入并提供原位重试。
5. Turnstile 不可用时显示明确的暂时不可用状态，不将请求静默放行。

### 6.5 前端状态机

```text
idle
  -> submitting
  -> success-copied
  -> success-copy-fallback
  -> challenge
      -> submitting
      -> challenge-error
  -> validation-error
  -> rate-limited
  -> dependency-error
```

每次新提交必须清理旧的成功或错误反馈，但不得在请求失败时清除用户输入。状态变更通过 `aria-live="polite"` 宣告；表单验证错误必须关联到具体字段。

## 7. 视觉与可访问性规格

### 7.1 视觉系统

- 页面背景为近黑色，不使用渐变球、光斑或纯装饰插画。
- 主要表面使用克制的深灰层级、细描边和不超过 `8px` 的圆角。
- 绿色仅用于在线状态、成功和唯一主操作；暖色仅用于到期与风险提示；错误使用独立红色。
- `myurl` 品牌、技术标签和 URL 使用本地托管的 IBM Plex Mono；中文正文使用系统字体。
- 字体和 Lucide 图标随应用打包，不使用 Google Fonts、unpkg 或其他运行时 CDN。
- 不使用夸张大卡片、嵌套卡片或营销式 Hero 布局。

### 7.2 交互反馈

- 按钮在 pointer down 时立即响应，按下缩放约为 `0.97`。
- 普通状态变化采用无回弹、可中断的短过渡。
- 提交状态必须立即可见，不引入人工等待时间。
- 结果出现不得改变输入区的水平尺寸或造成页面跳动。
- `prefers-reduced-motion: reduce` 时移除位移动画和弹性效果，仅保留必要的淡入或颜色反馈。
- `prefers-reduced-transparency: reduce` 时使用实色表面并关闭模糊。
- `prefers-contrast: more` 时提高文字、边框和焦点环对比度。

### 7.3 响应式与无障碍

- 目标桌面视口：`1440 × 900`；目标移动视口：`390 × 844`。
- 最低支持页面宽度：`320px`。
- 移动端 URL 输入和主操作可纵向排列，主操作宽度为 `100%`。
- 所有交互控件触控目标至少为 `44 × 44px`。
- 所有功能必须可通过键盘完成，并提供清晰的 `:focus-visible` 样式。
- 表单、状态、结果和外部链接使用原生语义，不使用无语义 `div` 模拟按钮。
- 文本对比度满足 WCAG 2.2 AA；颜色不是表达成功、警告或错误的唯一方式。
- 支持 Chrome、Edge、Firefox、Safari 最近 2 个稳定大版本，以及当前和前一大版本的 iOS Safari、Android Chrome。

## 8. 系统架构

### 8.1 运行拓扑

```text
浏览器
  -> 部署者自有公网入口（项目范围外）
  -> 127.0.0.1:${APP_PORT}
  -> app 容器 :3000
       |- Svelte/Vite 静态产物
       |- Fastify JSON API
       |- 短链 302 跳转
       `- ShortLinkService
            `- Redis Adapter
                 -> redis 容器 :6379（仅 Compose 内网）
```

Compose 仅定义 `app` 和 `redis`。`app` 在容器内监听 `0.0.0.0:3000`，宿主机默认映射为 `127.0.0.1:${APP_PORT:-3000}:3000`。Redis 不发布宿主机端口。

### 8.2 应用边界

对外业务接口保持小而深：

```ts
export interface ShortLinkService {
  create(input: CreateLinkInput): Promise<CreateLinkResult>;
  resolve(code: string): Promise<ResolvedLink | undefined>;
}
```

`ShortLinkService` 隐藏以下复杂度：

- URL 解析、规范化和目标策略。
- 自定义别名规范、保留字和冲突。
- 自动短码生成及有限碰撞重试。
- 风险计分、限流和 Turnstile 验证。
- Redis 原子创建、读取和错误归一化。
- 固定 90 天到期时间计算。

Fastify 路由只负责 JSON Schema 验证、可信请求上下文提取以及领域结果到 HTTP 的映射。Svelte 只依赖 HTTP 合同，不知道 Redis 键、限流算法或 Turnstile 密钥。

### 8.3 代码组织

```text
apps/
  web/                 Svelte + Vite 页面、状态与交互
  server/              Fastify、ShortLinkService、基础设施适配器
packages/
  contracts/           共享 JSON Schema、TypeScript 类型、错误码
tests/
  e2e/                 Playwright 完整用户流程
ops/                    Compose、备份、恢复、部署检查
```

`contracts` 是唯一共享包。不得为了形式引入 Controller、Manager、Repository 等无实际隐藏能力的空壳层。Redis Adapter 和 Turnstile Adapter 是真实外部边界，可通过测试实现替换。

## 9. HTTP 合同

### 9.1 创建短链

**Method：** `POST`

**Path：** `/api/v1/links`

**Content-Type：** `application/json`

**请求体上限：** `16 KiB`

请求：

```json
{
  "url": "https://example.com/articles/launch",
  "alias": "launch",
  "challengeToken": "optional-turnstile-token"
}
```

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| `url` | string | 是 | UTF-8 编码后不超过 4096 字节 |
| `alias` | string | 否 | 规范化后匹配 `[a-z0-9_-]{4,32}` |
| `challengeToken` | string | 否 | 仅在收到挑战后提交，最大 2048 字节 |

成功响应：`201 Created`

```json
{
  "code": "launch",
  "shortUrl": "https://myurl.example/launch",
  "expiresAt": "2026-11-24T12:00:00.000Z"
}
```

`shortUrl` 必须从 `PUBLIC_BASE_URL` 和服务端生成的 code 组合，不读取或信任请求 `Host` 头。`expiresAt` 是创建成功时刻加 `7,776,000` 秒的 UTC ISO 8601 时间。

### 9.2 短链跳转

**Method：** `GET` 和 `HEAD`

**Path：** `/:code`

- 命中：返回 `302 Found`，`Location` 为存储的目标 URL。
- `HEAD` 与 `GET` 使用相同解析语义但不返回响应体。
- 非法格式、不存在或已过期：返回 `404 Not Found`。
- Redis 故障：返回 `503 Service Unavailable`，不得误报为 `404`。
- 跳转响应包含 `Cache-Control: no-store`、`Referrer-Policy: no-referrer` 和 `X-Robots-Tag: noindex, nofollow`。

解析入口只接受匹配 `[0-9A-Za-z_-]{4,32}` 的单路径段。浏览器 `GET` 的 `404` 和 `503` 返回同一视觉系统下的最小 HTML 错误页；`HEAD` 只返回状态和响应头。错误页不得显示 Redis、短码规则或内部错误细节。

`/`、`/api`、`/api/*`、`/assets`、`/assets/*`、`/health`、`/health/*` 和其他保留路径必须在动态短码路由之前注册。

### 9.3 健康检查

- `GET /health/live`：只验证 Node.js 进程和事件循环可响应，不访问 Redis。
- `GET /health/ready`：在短超时内执行 Redis `PING`；失败返回 `503`。
- 健康检查不返回版本密钥、Redis 地址或内部异常堆栈。

### 9.4 错误结构

除短链跳转的浏览器错误页外，JSON API 错误统一为：

```json
{
  "error": {
    "code": "alias_unavailable",
    "requestId": "req_01J...",
    "retryAfterSeconds": 120
  }
}
```

`retryAfterSeconds` 仅在可以提供可靠重试时间时出现。API 不返回面向用户的中文文案；前端根据稳定错误码映射本地文案。

| HTTP | 错误码 | 语义 |
| --- | --- | --- |
| `400` | `invalid_request` | JSON、字段类型、长度或结构不合法 |
| `403` | `challenge_required` | 必须完成 Turnstile，响应附公开 site key |
| `403` | `challenge_invalid` | token 无效、过期、重复使用或验证不匹配 |
| `409` | `alias_unavailable` | 别名已存在或属于保留字 |
| `422` | `url_not_allowed` | URL 无法解析、不是绝对 HTTP(S) 地址或被目标策略拒绝 |
| `422` | `alias_invalid` | 别名规范化后不满足规则 |
| `429` | `rate_limited` | 已超过创建频率或风险上限 |
| `503` | `dependency_unavailable` | Redis 或挑战验证依赖不可用 |
| `503` | `code_generation_exhausted` | 自动短码连续碰撞达到上限 |

`challenge_required` 响应额外包含：

```json
{
  "error": {
    "code": "challenge_required",
    "requestId": "req_01J..."
  },
  "challenge": {
    "provider": "turnstile",
    "siteKey": "public-site-key"
  }
}
```

## 10. 短码与目标 URL 规则

### 10.1 自动短码

- 使用 Node.js 密码学安全随机源生成。
- 字符表为 Base62：`0-9A-Za-z`。
- 固定长度为 8，大小写敏感。
- 每次生成后通过 Redis `NX` 原子占用；冲突时最多重新生成 5 次。
- 生成结果若命中保留路径，视为碰撞并重试。
- 5 次均失败时返回 `code_generation_exhausted`，不得回退到可预测序列。

### 10.2 自定义别名

- 读取后先执行 Unicode 前后空白裁剪，再转换为 ASCII 小写。
- 规范化后必须匹配 `[a-z0-9_-]{4,32}`。
- 不允许 Unicode 同形字符、百分号、斜杠、点、空格或 URL 编码绕过。
- 保留字比较不区分大小写。
- 初始保留集合至少包括：`api`、`assets`、`health`、`favicon.ico`、`robots.txt`、`sitemap.xml`。
- 自定义别名与自动短码共享同一 Redis 命名空间，Redis `NX` 是并发竞争的唯一裁决。

### 10.3 目标 URL

- 输入在解析前按 UTF-8 字节数限制为 4096 字节。
- 使用标准 `URL` 解析器，不通过正则表达式手写 URL 解析。
- 只接受绝对 `http:` 和 `https:` URL。
- 必须存在 hostname；拒绝 username、password、控制字符和嵌入空白。
- 拒绝 `localhost`、其子域、`.local`、`.internal`、`.home.arpa`。
- 拒绝字面量 IPv4 或 IPv6 的回环、私网、链路本地、未指定、组播和文档保留地址。
- 允许显式端口、查询参数和片段。
- 存储标准 `URL.href` 序列化结果。

服务端不会连接、解析 DNS、抓取或预览目标 URL，因此不引入服务端请求伪造（SSRF）面。域名将来解析到私网地址不会导致 MyURL 服务端访问该地址；v2 首版不做 DNS 解析或重绑定检测。

## 11. Redis 数据模型

### 11.1 短链

```text
Key:   myurl:link:{code}
Type:  string
Value: 规范化后的目标 URL
TTL:   7,776,000 秒
```

创建必须使用等价于以下语义的单条原子命令：

```text
SET myurl:link:{code} {targetUrl} NX EX 7776000
```

不额外存储创建者 IP、创建时间、点击次数或用户代理。创建响应中的 `expiresAt` 由应用时钟计算；Redis TTL 是实际过期权威。

### 11.2 限流与风险键

所有来源标识使用 `HMAC-SHA-256(IP_HASH_SECRET, canonicalIp)`，键中只保存摘要，不保存原始 IP。

```text
myurl:rate:create:10m:{fingerprint}
myurl:rate:create:1d:{utcDate}:{fingerprint}
myurl:risk:create:10m:{fingerprint}
```

- 10 分钟计数器首次写入时设置 600 秒 TTL。
- 每日计数器在 UTC 日期变化后使用新键，TTL 设置为不超过 48 小时。
- 风险计数器 TTL 为 600 秒。
- 计数递增与首次 TTL 设置必须在 Redis Lua 脚本或等价原子操作内完成。
- 任何 Redis 故障均不得退化为无限制创建。

## 12. 渐进式风控

### 12.1 默认阈值

| 条件 | 默认行为 |
| --- | --- |
| 同一指纹 10 分钟内第 1–5 次创建 | 无挑战，继续处理 |
| 同一指纹 10 分钟内第 6–20 次创建 | 要求有效 Turnstile |
| 同一指纹 10 分钟内超过 20 次 | 返回 `429` |
| 同一指纹 UTC 日内超过 100 次 | 返回 `429` |
| 10 分钟风险分达到 3 | 即使未到第 6 次也要求挑战 |
| 10 分钟风险分达到 8 | 返回 `429` |

默认风险分：

- 目标 URL 被策略拒绝：`+1`。
- 别名格式不合法：`+1`。
- 自定义别名冲突：`+1`。
- Turnstile 验证失败：`+3`。

阈值必须可通过环境变量调整，但生产默认值必须与本文档一致。配置解析失败时应用拒绝启动。

### 12.2 判定顺序

1. Fastify 验证 JSON 结构和字段上限。
2. 从直接连接或已配置的可信代理中取得规范化客户端 IP，并生成 HMAC 指纹。
3. 原子递增 10 分钟及每日创建计数。
4. 超过绝对上限时返回 `429`。
5. 读取风险分；需要挑战且无 token 时返回 `challenge_required`。
6. 需要挑战且有 token 时验证 Turnstile；失败增加风险分并返回 `challenge_invalid`。
7. 执行 URL 与别名业务策略；被拒绝时增加对应风险分。
8. 执行 Redis 原子短链创建。

### 12.3 Turnstile 边界

- Turnstile 仅在服务端要求挑战后由前端按需加载。
- 生产环境验证 `success`、预期 hostname 和 action `create_link`。
- token 不记录、不缓存、不复用，也不得出现在错误文本中。
- Turnstile 服务不可用时，仅已被要求挑战的请求返回 `dependency_unavailable`；低风险请求不依赖外部验证服务。
- CI 使用测试适配器或 Cloudflare 官方测试密钥，不调用真实生产验证服务。
- 隐私声明必须说明：原始 IP 不写入 MyURL 存储或日志，但用户完成挑战时会直接与 Cloudflare 服务交互。

## 13. 安全与隐私

### 13.1 代理信任

- 应用默认不信任 `X-Forwarded-For`、`Forwarded` 等转发头。
- 部署者通过 `TRUST_PROXY_CIDRS` 显式配置可信代理 CIDR，生产环境禁止使用无边界的「信任全部」。
- 未配置可信代理时，以直接 TCP 对端地址作为客户端 IP。
- 配置非法 CIDR 时应用拒绝启动。

### 13.2 HTTP 安全

- API 仅接受 `application/json`。
- 存在 `Origin` 头时，其 origin 必须与 `PUBLIC_BASE_URL` 一致；无 `Origin` 的非浏览器客户端允许访问。
- 静态页面配置严格 CSP，只允许同源脚本、样式、字体和资源，以及按需加载的 Turnstile 官方来源。
- 应用层设置安全响应头，不依赖部署者的反向代理补齐核心安全配置。
- 不回显内部堆栈、Redis 键、环境变量或第三方验证响应。
- 请求、Redis 和 Turnstile 调用均设置明确超时；客户端断开后取消不再需要的外部工作。

### 13.3 日志隐私

允许记录：

- `requestId`、时间、路由模板、HTTP 状态码、耗时。
- 业务结果分类、Redis/Turnstile 依赖分类、限流决策。
- 应用版本和非敏感启动配置摘要。

禁止记录：

- 原始 IP 或完整 HMAC 指纹。
- 完整目标 URL、短码、自定义别名或 `Location`。
- Turnstile token、密钥、Redis URL 中的凭据。
- 原始请求体、响应体或敏感请求头。

## 15. 前端工程设计

### 15.1 页面结构

`apps/web` 使用 Svelte 和 Vite。首版只有一个页面，不引入客户端路由器。前端组件按真实职责划分：

- `BrandHeader`：品牌和服务状态。
- `LinkComposer`：URL、别名、提交和字段错误。
- `TurnstileChallenge`：仅在挑战状态挂载。
- `LinkResult`：结果、自动复制状态和再次复制。
- `ProjectFooter`：GitHub、订阅转换和许可证入口。

状态机保留在页面级 feature 模块中，不引入全局状态库。HTTP client 只消费 `packages/contracts` 的合同。

### 15.2 资源与字体

- IBM Plex Mono 字体文件和 OFL 许可证随仓库存放并进入构建产物。
- Lucide 以包依赖形式按需导入，构建后不产生运行时 CDN 请求。
- 除按风险加载的 Turnstile 外，页面运行不依赖第三方资源。
- GitHub 与订阅转换只在用户主动点击时导航，不在页面加载时预取。
- GitHub 与订阅转换均在新标签页打开，并使用 `rel="noopener noreferrer"`。

### 15.3 复制策略

1. 首选 `navigator.clipboard.writeText(shortUrl)`。
2. 失败时结果仍显示，并将整个结果表面切换为明显的可点击复制控件。
3. 再次点击仍失败时保留可选择的完整文本，并提示浏览器阻止访问。
4. 不通过隐藏输入、焦点劫持或循环弹窗制造虚假成功状态。
5. 只有实际复制 Promise 成功时才能显示「已复制」。

## 16. 依赖与版本策略

- 使用 pnpm workspace、ESM 和严格 TypeScript。
- 启用 `strict`、`noUncheckedIndexedAccess`、`exactOptionalPropertyTypes` 和 `useUnknownInCatchVariables`。
- HTTP Schema 使用可生成 JSON Schema 和静态类型的单一合同定义，禁止手写两套漂移的类型。
- Redis 使用维护活跃且支持原子命令、Lua 和连接生命周期管理的稳定 Node.js 客户端。
- 实施启动时从官方发布源核实 Node.js 活跃 LTS 和所有直接依赖的最新稳定兼容版本，并将精确版本及 `packageManager` 固定到清单和锁文件。
- 禁止 `latest`、`*` 或未锁定范围进入可发布构建。
- 每周自动提出补丁和次版本升级；主版本升级必须独立验证，不自动合并。
- 直接依赖必须说明用途；能够用平台标准 API 清晰解决的问题不引入额外包。

## 17. 可观测性与运行行为

### 17.1 日志

Fastify/Pino 以单行 JSON 输出到 stdout。每个请求必须有稳定 request ID；上游提供的 ID 仅在格式和长度满足约束时采用，否则服务端生成。错误日志使用分类字段，不输出用户数据或完整第三方响应。

### 17.2 超时与关闭

- Redis、Turnstile 和服务器请求必须有明确超时配置，默认值在实现计划中固定并测试。
- 收到 `SIGTERM` 后停止接受新连接，等待进行中的请求在有限窗口内完成，然后关闭 Redis 连接并退出。
- 就绪检查在关闭开始后立即失败，避免上游继续分发流量。

### 17.3 性能目标

在 2 vCPU、2 GB 内存、应用与 Redis 位于同一主机 Docker 网络的参考环境中，预热 30 秒后执行 60 秒测试：

- 低风险创建路径，在并发 10 且使用不同测试来源指纹时，服务端处理 `p95 ≤ 100 ms`。
- 已存在短链解析，在并发 50 时，服务端处理 `p95 ≤ 50 ms`。
- 错误率小于 `0.1%`，不包含主动构造的限流和校验错误。
- Turnstile 外部网络耗时单独报告，不计入低风险创建门槛。

性能测试用于发现明显回归，不替代真实生产容量规划。

## 18. 部署、持久化与恢复

### 18.1 Compose 交付

- `app` 使用多阶段构建：先构建 Svelte 和 TypeScript，再生成只包含生产运行所需文件的镜像。
- `app` 以非 root 用户运行，提供容器健康检查和只读文件系统可行性验证。
- `redis` 只连接 Compose 内部网络，不发布端口。
- Redis 使用命名卷；v2 创建独立卷，不复用 v1 数据目录或卷。
- 镜像使用不可变提交 SHA 标签；语义版本标签只作为附加别名。

### 18.2 Redis 持久化

- 启用 AOF `appendfsync everysec`。
- 同时启用 RDB 快照作为恢复补充。
- 容器重启不得删除命名卷。
- 磁盘空间不足、AOF 写入失败或 Redis 未就绪时，应用创建与解析返回 `503`，不得继续假装健康。

### 18.3 备份与恢复

- `ops/` 提供可审计的备份和恢复脚本，不把备份写入 Git。
- 默认每日生成 1 次 Redis 备份，保留最近 7 日。
- 文档要求部署者将备份复制到异机或对象存储；只保留在同一 VPS 不构成灾难恢复。
- 恢复流程必须在停止写入、校验备份、恢复到新卷、启动 Redis、运行短链抽样验证后才允许切换。
- 单 VPS 目标：`RPO ≤ 24 小时`，`RTO ≤ 2 小时`。
- 每个候选发布至少执行 1 次干净环境恢复演练并保存结果摘要。

### 18.4 范围外责任

部署者负责公网入口、TLS、域名解析、证书续期、主机防火墙、备份异机存储和日志收集平台。项目文档只说明入口应转发到 `127.0.0.1:${APP_PORT}`，不生成具体代理配置。

## 22. 风险与取舍

### 22.1 单 VPS 不提供高可用

`app + redis` 的最小部署降低了运维成本，但主机故障会导致整体不可用。AOF、RDB 和异机备份提供可恢复性，不提供零停机或零数据丢失。若未来需要高可用，应单独设计 Redis 和应用多副本拓扑，不能假设本规格已经覆盖。

### 22.2 Redis 是唯一数据权威

Redis TTL 与原子占用非常适合固定 90 天的匿名短链，但不适合未来的复杂查询、审计或长期资产管理。账号、统计、编辑或永久链接出现时，应重新评估持久化模型，而不是在当前键值结构上堆叠隐藏元数据。

### 22.3 自动复制受浏览器策略约束

网络请求返回后，部分浏览器可能不再认为当前代码处于有效用户激活中。实现只能准确尝试并反馈，不能绕过浏览器权限。整条结果点击复制是必要降级，不属于可删除的冗余按钮。

### 22.4 公开短链存在滥用风险

限流和 Turnstile 可降低自动化滥用，但不能保证目标内容安全。v2 不抓取目标、不做恶意网址判定，也不提供人工管理后台；严重滥用处置需要未来单独设计停用和运营流程。

### 22.5 反向代理配置影响来源识别

项目不交付反向代理，但风控依赖真实来源 IP。错误信任转发头可能造成限流绕过或所有用户共享同一指纹，因此生产部署必须验证 `TRUST_PROXY_CIDRS`，并把该验证列入部署检查。

## 23. 变更控制

本规格批准后，以下变更必须先更新设计并重新确认，不能在实现阶段自行扩大：

- 新增账号、统计、管理或用户自定义域名。
- 改变 90 天 TTL 或支持用户选择 TTL。
- 改变短码字符集、长度或大小写语义。
- 引入 Redis 之外的数据库或队列。
- 将反向代理重新纳入项目 Compose。
- 添加目标 URL 抓取、DNS 解析或内容预览。
- 改变已批准的主流程和 UI 信息架构。

低风险实现细节可在不改变合同的前提下由实现计划确定，但必须有对应测试和回滚方式。
