# MyUrls 日志与时区加固设计

## 目标

在不改变 CLI、环境变量、`POST /short`、短链响应结构和内置页面的前提下，降低日志中的敏感信息与健康检查噪音，并让容器和应用日志稳定使用中国标准时间。

## 方案

- 访问日志只记录请求方法、Gin 路由模板、状态码和耗时。使用 `c.FullPath()`，让真实短码只显示为 `/:shortKey`；未匹配路由统一显示为 `unmatched`。
- 成功的 `GET /healthz` 不写访问日志；非成功健康检查仍保留，便于发现 Redis 或应用异常。
- 移除默认访问日志中的客户端 IP 和 User-Agent。它们不是排查短链服务正常运行的必要字段。
- 所有 Zap 时间字段显式转换到固定 `+08:00` 时区。镜像同时复制 `Asia/Shanghai` 时区文件并设置 `TZ`，覆盖应用自身及未来依赖的本地时间行为。
- Compose 为 MyUrls 和 Redis 的标准输出日志设置轮转上限。MyUrls 自有 `access.log` 继续使用 Lumberjack 轮转。

## 安全边界

- 不记录 Query、请求体、Authorization、Redis 密码、API Token、完整长链接或真实短码。
- 健康检查成功记录被抑制，但健康检查本身保持不变。
- 日志读取权限与 Docker 管理权限仍属于部署者责任。

## 验证

- 单元测试验证路由模板、短码隐藏、成功健康检查跳过、失败健康检查保留和 `+08:00` 时间编码。
- 静态部署测试验证 Dockerfile 时区文件和 Compose 日志轮转。
- 完整执行 `go test ./...`、`go vet ./...`、格式检查和容器构建。
