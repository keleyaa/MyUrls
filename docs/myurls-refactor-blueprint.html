01 / Thesis

少代码，是结果，不是约束

主目标：减少概念数量、隐藏耦合和修改触点。
硬约束：旧 API、Redis 数据格式、安全边界与核心用户体验不能退化。

保留单一 main package

当前体量无需 Clean Architecture。按文件职责分组即可，不拆出 usecase、presenter 或 DI container。

显式依赖，不堆接口

只引入最小 Store；随机短码用函数注入。App 负责业务，HTTP 负责旧契约。

删除旧路径

删除 ShortToLong、LongToShort、Renew 等已脱离生产路径的 helper 及重复测试。

缩窄运维承诺

日志统一 stdout；保留备份恢复和受支持升级，不长期维护跨 Redis major 原地降级流程。

04 / Contract

必须锁定的外部行为

行为保持内容边界
创建POST /short；form、multipart、JSON；字段 longUrl/shortKey成功仍为 HTTP 200、Code:1
业务错误多数错误仍 HTTP 200，由 Code 表达错误映射集中，不顺手 REST 化
跳转301；缺失 404；Redis 故障 500不改 302/307/308
数据裸 Redis key、string value、365 天 TTL、SetNX不加 namespace，不迁移 schema
短码7 位 base62；最多 5 次碰撞；大小写敏感保留路由保留词
输入绝对 HTTP(S)、无 userinfo；保留 Base64 fallback不扩大 scheme

纯重构
08

收束文档

README 作为入口；运维文档只描述受支持路径、stdout 日志、备份和恢复。

文档边界
每阶段独立提交。 只有当前阶段的单测、race、集成、E2E 或 Compose 门禁全部通过，才能进入下一阶段。
06 / Gate

完成门槛

  • form 与 JSON 创建保持精确旧响应
  • 冲突、Base64、大小写和 301 契约通过
  • 真实 Redis 的 Claim、TTL、Resolve 通过
  • go test -race ./... 通过
  • Compose 传递 legacy 与 Redis URL 配置
  • 容器安全属性不退化
  • stdout 不出现短码、目标 URL、token 或凭据
  • Playwright 主路径及无障碍通过
  • 业务层不存在 package-global Redis/logger
  • 旧 Redis helper 全部删除
  • App 只承担验证、创建、解析
  • 提交前后复杂度指标有对比

主要指标

一次创建请求需要跨越的文件与概念数；修改一个业务规则需要触碰的文件数。

辅助指标

生产 LOC、测试 LOC、全局变量、配置项、接口数量。LOC 不作为硬性成功条件。

07 / Boundary

明确不做

不扩张产品

不增加账户、多租户、统计、管理后台、删除 API、自定义 TTL 或短码命名空间。

不扩张架构

不引入 Clean Architecture、DDD 聚合、事件总线、DI 容器、前端框架或外部 CDN。

不偷改协议

不修改字段大小写、业务错误 HTTP 200、301、Base64 兼容、TTL、字符集或重试次数。

不迁移数据

不改变 Redis key schema；跨 Redis major 仅支持先在隔离环境恢复演练再切换流量，不支持原地升级或回退。
